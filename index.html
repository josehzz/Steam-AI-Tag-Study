How This Was Built

  • Data comes from Steam public game pages, I built a scraper using Claude to get relevant data like:

    • Name, Tags, Review Count, Review Score, Review Description, Release Date, Base Price (USD) and AI Disclosure

  • I placed all the data inside a .csv, that I then cleaned by:

    • Finding empty/null entries on review_count column and setting them to 0
    • Finding empty/null entries on review_score column and setting them to 0.0
    • Finding empty/null entries on review_desc column and setting them to "0 user reviews"

  • To process the data inside the AI disclosure tag I used Gemini to synthesize data into 10 different tags, then I asked it to set up agents that would read the contents of each entry that has a disclosure and classify that into those tags (a single game can have multiple):

    • Visual: Game has art assets made with AI
    • Audio: Game has audio assets made with AI
    • Text: Game has text generated with AI
    • Code: Game has code generated with AI
    • Prototyping: Some assets were generated as placeholder to help with production and development of the game
    • Live_Generated: Some assets inside the game are generated while playing
    • Marketing: Some assets were generated with AI for marketing purposes (Capsule art, Promotional Images and Videos, Social Media Campaigns, etc...)
    • External_Ai_service: Game links to an AI service (like Claude, Gemini, OpenAI)
    • Declares_No_Ai: Game features no AI generated content
    • Unspecified: Some disclosures say they may have AI generated content but don't specify how or where

  • This dataset is available here: https://www.kaggle.com/datasets/josehzz/steam-games-jan2024-nov2026-with-ai-tags/data

  • Then using Gemini I made this dashboard where I divided the project into different sections

    • Is It Relevant? Graphs and data that show the relevance of AI-generated content
    • More Info Overall data that provides additional context
    • For Fun Experiments I wanted to run
    • Boring stuff devs are curious about For developers that want to see recent trends, patterns, and opportunities
    • Conclusions TLDR of the findings

  • I audited Gemini's multi-label tags against 300 randomly sampled disclosures by manually tagging them (87.7% Micro F1, 77.3% exact match). For languages I didn't know, I used the browser translator (2 or 3 times).

  • The tool I used to manually tag the 300 random entries is available here: https://github.com/josehzz/Steam-AI-Tag-Study/tree/main/Manual%20AI%20Disclosure%20Tagging

Limitations

  • There are some games released before Jan-2024 that added the AI disclosure tag not included in this dataset

  • Some games can feature content made by players, these games often say they don't use AI assets, but players might do so. This was classified as Declares_No_Ai.

  • This data was collected and consolidated between Nov-02-26 and Nov-11-26, so recently released games stats might vary a lot.

  • AI Disclosures are self reported meaning that there might be games that did not disclose their AI use, I think most developers are truthful but in practice the true amount of AI usage must be a little bit more

  • In the 300-game manual audit, core modality tags (Visual, Audio, Marketing, Code, Text) achieved 83.6%–94.7% F1, while Prototyping (20.6% recall) and Unspecified (28.6% recall).

  • AI-tagged games skew heavily toward low price tiers (avg $6.03 vs $7.90) and mature-flagged titles (30.36% AI share).

Common Failure Modes Spotted (n = 300)

68 mismatches analyzed

  • Prototyping Tag: When disclosures describe AI used "during development", temporary demo copy, or hybrid pipelines where AI drafts are manually edited the classifier usually applied only the final asset modality (Visual/Text) and omitted Prototyping.

  • Unspecified Tag: Negated clauses ("does not use AI to generate images"), generic statements ("some assets" guessed as Visual instead of Unspecified, missing 10 of 14), and non-generative AI produced the bulk of false positives.

It is, but data suggest is not a simple yes or no

TLDR

📈

Can a game that disclosed its AI usage be successful?

Yes (maybe). The more reviews a game has the less likely it is to have an AI tag. Regardless we see successful games with +1000 reviews, with a positive score with the AI tag and many others on the far opposite side without the AI tag. I think this reflects that Steam users like to buy good quality games, just like it always has been.

🏷️

Why so many games made with AI?

AI usage concentrates in the $0.01-$4.99 price range, also the lower the price the lower the score and review count. I read this as AI lowering the bar for people to get into game development but also making the Steam store be filled with more shovelware than usual. Also we have to consider that AI development is a new trend and when something is popular a lot of people are going to try it, just because.

⚖️

So why does it feel like a penalty to have the AI Disclosure?

The data suggest a penalty for AI usage, and sadly even though it is small for score (-4.07 on average) and review count (41.6% lower odds of reaching +10 reviews), I don’t think is just because AI. I think this “penalty” is mostly because of inexperienced developers flooding the store and skewing the averages.

🧩

Why the Multiplayer tag is rarely seen linked to AI Usage?

This is an interesting one where seems like developers that use AI are not making multiplayer, co-op, open world or similar tagged games when these tags are the biggest drivers of review count for Steam games. Singleplayer, Casual, Indie, Simulation and Strategy rank high on AI usage which are often popular tags for small development teams. So I wonder if this is because AI is still new and can’t handle Multiplayer code or developers of this type of games are slow at incorporating this technology, or maybe a little bit of both.
